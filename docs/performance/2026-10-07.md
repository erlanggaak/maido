# Maido performance and readability — 7 October 2026

Source readability is improved without a meaningful change in measured idle performance.
The final paired samples both sustained the configured 30 FPS. Average measured CPU work
was 3.219 ms before and 3.180 ms after; the ~1.2% difference is within the noise of this
single pair of real-time samples, and is not evidence of a speedup.

## Measurement conditions

- User machine: MacBook Pro M4, 16 GB (user supplied).
- Codex in-app Chromium browser, Chrome 154 on macOS; production Vite builds.
- One agent-created rendering tab at a time; no builds or test runs during final sampling.
- Same viewport: 682 × 797 CSS pixels, renderer pixel ratio 1.75.
- Same avatar: `AvatarSample_D.vrm`; 8 animation assets; happy resting mood, idle life on,
  faithful lighting, soft spring physics, breeze and manga symbols enabled.
- Frame cap explicitly set to 30 in both benchmark origins; settings drawer closed.
- Five-second warmup after resetting the profiler. Before: 1,322 frames (~44 seconds);
  after: 1,087 frames (~36 seconds). Raw samples are aggregated in a 1,800-frame ring.
- Original source from HEAD built in a temporary directory with equivalent profiling
  instrumentation. Current source built in the workspace. Test history was a dummy fixture;
  no LLM requests were made, and the user's history/profile were not edited.

## Interpretation and limits

The frame profiler measures JavaScript/CPU elapsed time and GPU command submission.
It does not measure GPU execution/completion, OS process RAM, power consumption, or
end-to-end LLM/TTS latency. Animation randomness and other machine activity are uncontrolled;
this is an idle workload, not a guarantee for larger models or active conversations.

Initial exploratory samples at 1280 × 720 showed ~59.4 FPS, but a later sample received
only 30 browser animation callbacks per second despite a 60 FPS app setting. Additional
rendering tabs and changes in browser cadence made those samples unsuitable for a causal
comparison. They are retained separately for transparency. The final controlled comparison
uses an explicit 30 FPS cap and matching viewport. It does not establish sustained 60 FPS
for the refactored build.

Body/physics updates and rendering dominate the measured work; director logic is small.
The tiny frame-loop changes cache normalized bone references per model and reuse the
arm-correction quaternion. Their benefit is not distinguishable in this measurement.
A Rust rewrite is not justified by this idle measurement. Profile a concrete slow workload
before choosing a larger optimization.

## Readability changes

- Prettier formats frontend, backend, and tests. `npm run format` writes formatting;
  `npm run format:check` checks it.
- `src/chat/ChatComposer.tsx`: input, keyboard handling, send/stop controls.
- `src/chat/ReplyBubble.tsx`: reply expansion and scrolling subtitles.
- `src/chat/useSpeech.ts`: streamed speech state and director callbacks.
- `src/chat/replyStream.ts`: network chunks → typed NDJSON events, UTF-8 decoding,
  final unterminated line handling, cancellation and reader cleanup.
- `src/settings/BrainForm.tsx`: provider/session settings separated from the sidebar.
- `src/avatar/rig.ts`: fallback mascot geometry and pose composition, separated from
  scene/model lifecycle in `AvatarViewer.tsx`.
- Backend/provider/director logic is otherwise formatted rather than redesigned.

## Repeat the measurement

1. `npm run build`, then `npm start`.
2. Open `http://localhost:4317/?profile` and load the desired character.
3. Set the same viewport, avatar, lighting, physics and FPS in each run. Close other
   rendering tabs and wait until all animation assets have loaded.
4. In browser DevTools, run `maidoPerformance.reset()`; keep the page visible and idle
   for at least 35 seconds (the first five seconds are excluded).
5. Read `maidoPerformance.snapshot()` or copy its JSON. Record browser cadence and
   environment alongside the result; do not compare differently sized/capped runs.

Profiling is opt-in via the `profile` query parameter. Normal mode does not collect samples
or call the per-stage timers. Profiling and renderer data stay local.

## Verification

Production build, TypeScript/server syntax checks, formatting check, and 21 tests passed.
The stream regression checks exercise split multi-byte UTF-8, blank lines, missing final
newline, early cancellation and network errors. Browser smoke checks cover avatar rendering,
character switching and reply fold/expand behavior. The production build still reports the
existing >500 kB Three.js/VRM vendor chunk warning; formatting does not reduce library size.
